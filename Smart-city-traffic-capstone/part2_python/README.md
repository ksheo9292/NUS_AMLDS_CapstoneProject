## Run the complete pipeline once

Open a terminal in this folder and run:

```bash
python pipeline.py
```

The command validates and cleans the raw data, creates features, saves `processed_traffic.csv`, produces four PNG figures and writes `pipeline.log`.

For detailed troubleshooting messages:

```bash
python pipeline.py --debug
```

## Use the command-line application

The application supports four queries:

```bash
python cli_app.py datetime "2017-09-30 12:00"
python cli_app.py high-traffic --threshold 5500 --limit 5
python cli_app.py compare
python cli_app.py recommend --day-type weekday --weather Clear
```

If `processed_traffic.csv` has not been created, run `python pipeline.py` first.

## Methodology

The pipeline performs these stages:

1. Loads the raw CSV with specific file and parsing exception handling.
2. Validates all nine expected columns before processing.
3. Standardises categorical values and parses `date_time`.
4. Removes fully duplicated rows.
5. Detects impossible temperature, rainfall, snowfall, cloud-cover and traffic values.
6. Imputes affected numerical values using month-specific medians.
7. Creates time, cyclical, weather, scaled numerical and congestion features.
8. Saves the processed dataset and four visualisations.

The data-driven congestion target uses traffic-volume quartiles:

- Low: at or below the first quartile
- Medium: above Q1 and at or below the median
- High: above the median and at or below Q3
- Severe: above Q3

## Figure interpretations

- `01_traffic_by_hour.png`: Traffic is highest during weekday commuting periods, with the strongest average demand in the late afternoon.
- `02_weekday_vs_weekend.png`: Weekday traffic is higher than weekend traffic, reflecting regular commuting demand.
- `03_traffic_by_weather.png`: Average traffic differs across weather groups, but rare conditions should be interpreted cautiously because they contain few records.
- `04_temperature_vs_traffic.png`: Temperature has only a weak relationship with traffic volume, so it should not be treated as a direct cause of congestion.

## Logging

Logs are written to both the console and `pipeline.log`. The format contains timestamp, level, module name and message.

- `DEBUG`: intermediate values such as congestion quartiles
- `INFO`: normal milestones such as loading data and saving outputs
- `WARNING`: recoverable changes such as removing duplicates or imputing outliers
- `ERROR`: a failure that prevents the requested operation from completing

Each module uses `logging.getLogger(__name__)`. Handlers are configured only by the executable entry-point scripts.
